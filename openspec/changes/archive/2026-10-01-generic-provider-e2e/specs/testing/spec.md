# Spec Delta

## ADDED Requirements

### Requirement: Terraform end-to-end tests cover both provider implementations
The GitHub Terraform end-to-end workflow SHALL run the same mock-backed lifecycle with standard and generic provider implementations in separately labeled jobs.

#### Scenario: Both provider implementations run in CI
- **WHEN** the GitHub Terraform end-to-end workflow runs
- **THEN** it generates, builds, and tests both provider implementations against the same mock-backed scenario, with separately identifiable logs and results

### Requirement: Terraform integration failures identify the implementation
The GitHub Terraform end-to-end workflow SHALL retain diagnostics and identify whether the standard or generic provider job failed.

#### Scenario: Standard and generic provider logs are distinct
- **WHEN** either provider implementation fails its Terraform lifecycle
- **THEN** the workflow names the failed implementation and retains its diagnostics in an implementation-specific log artifact

### Requirement: Ansible end-to-end tests cover both schema sources
The GitHub Ansible end-to-end workflow SHALL run the same mock-backed role and playbook lifecycle using both the Ansible-generated schema and a schema generated by the generic Terraform provider path.

#### Scenario: Ansible workflow consumes the generic-generated schema
- **WHEN** the generic schema variant runs in GitHub Actions
- **THEN** `jtaf-xml2yaml` uses the generic-generated schema and the workflow runs the same NETCONF mock playbook lifecycle as the standard schema variant

#### Scenario: Ansible logs identify the schema source
- **WHEN** either schema variant runs
- **THEN** the job and uploaded integration logs identify whether the Ansible-generated or generic-generated schema was used
