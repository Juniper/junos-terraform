# Design

## Context

See proposal.md for motivation. GitHub already has mock-backed Terraform and Ansible lifecycle workflows. Terraform's `--generic` option selects a distinct provider implementation. Ansible has no generic role backend, but its YAML converter consumes the generated schema, allowing the same Ansible lifecycle to compare its normal schema with a generic-generated schema.

## Goals / Non-Goals

**Goals:**
- Run the Terraform mock lifecycle for both provider implementations with visible matrix labels and distinct log artifacts.
- Run the Ansible mock lifecycle for both schema sources using the same role and playbook scenario.
- Ensure the Python generic workflow test has Go available to build the generated provider.
- Make failures actionable and fix generic-provider defects demonstrated by the end-to-end pass.

**Non-Goals:**
- Connecting to live Junos devices; both CI comparisons use existing NETCONF mocks.
- Adding a generic Ansible role backend or changing either integration scenario.
- Fixing unrelated failures discovered while running the broader repository test suites.

## Decisions

### Use a GitHub Actions matrix for Terraform

Run the existing Terraform mock-backed integration job with a `standard`/`generic` provider implementation matrix. Each leg performs the same generation, build, Terraform lifecycle, and NETCONF mock checks in an isolated runner. Label each job and uploaded log artifact with the implementation so results are directly comparable in Actions.

**Alternative considered:** Sequentially swapping provider binaries in one job. Rejected because separate matrix jobs isolate generated files and produce clearer per-implementation results.

### Compare Ansible through its schema handoff

Run the existing Ansible mock-backed integration with a `standard`/`generic` schema-source matrix. The standard leg uses the schema generated by `jtaf-yang2ansible`; the generic leg runs `jtaf-yang2go --generic` and passes its schema to the same `jtaf-xml2yaml` conversion. Both legs use the same generated Ansible role, host configuration inputs, and mock playbook lifecycle. This exercises generic schema compatibility in Ansible without implying that a generic Ansible backend exists.

### Fix only test-reproduced generic-provider defects

Use the generic pass to reproduce defects and add the narrowest regression check at the owning layer. Keep unrelated failures out of this change; report them rather than expanding scope.

## Risks / Trade-offs

- [Generic provider behavior may fail existing lifecycle assertions] → Keep the matrix leg and diagnostics visible; use its failure to drive focused fixes.
- [Generic schema generation needs Go in the Ansible job] → Install Go only on the generic matrix leg.

## Migration Plan

No user migration is required. CI continues to use isolated runners and mock devices; no live targets or developer provider installations are affected.
